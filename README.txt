業務研究室 Ver.1.4.1 — iPhoneのバックアップ復元修正版
=================================================

■ 今回の修正
・iOS「ファイル」アプリで .brlab ファイルが選択できない現象に対応。
・復元ファイルの選択形式制限（accept属性）を削除しました。
・ファイルを選んだ後に暗号化形式をチェックし、正しくないファイルは復元しません。
・選択したファイル名の表示、エラーメッセージを改善しました。
・暗号化方式、バックアップファイルの中身、既存データの保存先に変更はありません。

■ iPhoneでの復元手順
1. GitHub Pagesの同じリポジトリに、解凍した全ファイルを上書きアップロードします。
2. iPhoneでアプリを起動し、オンライン状態で「設定」→「新しい版を確認」。
3. 更新が見つかったら「更新を適用して再起動」を選びます。
   設定に「Ver.1.4.1」と表示されれば更新完了です。
4. 「設定」→「バックアップから復元」を選びます。
5. ファイル選択欄をタップし、メニューの「ファイルを選択」から
   「このiPhone内」や「iCloud Drive」の .brlab ファイルを選びます。
6. バックアップ作成時のパスワードを入力し、「内容を復元する」をタップ。
7. 置き換え確認が表示されたら内容を確認し、問題なければ承認します。

■ 注意
・復元すると、使用中のiPhoneアプリに保存されている記録は置き換わります。
・バックアップファイルはGitHub上にアップロードしないでください。
・Safariとホーム画面アプリの保存データが別になることがあります。
・端末での動作はiPhone実機テストを行っていません。

==================== Ver.1.4の説明 ====================

業務研究室 Ver.1.4 — iPhone用PWA対応版
====================================

■ この版で追加・改善したもの
・iPhoneの「ホーム画面に追加」向けアイコン（180px Apple Touch Icon、192/512px PWAアイコン）
・アプリとして起動する設定（manifest.webmanifest）
・オフライン起動用のService Worker（sw.js）
・設定画面の「オフライン利用・更新状況」表示と更新操作
・ネット接続状況の表示
・GitHub PagesのサブフォルダURLに対応した相対パス
・Ver.1.3のデータ保存形式を維持（IndexedDBの名称とレコード形式は変更なし）

重要: 初回アクセスはインターネット接続が必要です。Service Workerがインストールされ、
設定画面に「オフライン起動の準備完了」と出てからオフラインで試してください。
SafariとiPhoneホーム画面アプリは保存領域が別になる場合があります。
バックアップを書き出して、利用したいホーム画面アプリ内で復元してください。

■ GitHub Pagesに無料で公開する基本手順
1. https://github.com でGitHubアカウントを作成・ログインします。
2. 右上の「+」→「New repository」で新しいリポジトリを作ります。
   名前例: gyomu-kenkyushitsu / Public（GitHub FreeでPagesを利用する場合）
3. ZIPを解凍し、「gyomu-kenkyushitsu」フォルダの中身を開きます。
4. リポジトリ画面の「Add file」→「Upload files」から、
   index.html, app.js, styles.css, sw.js, manifest.webmanifest,
   各種アイコンファイル等を、リポジトリの一番上（ルート）へアップロードします。
   注意: 「gyomu-kenkyushitsu」フォルダそのものをルートに置かないでください。
   index.html がトップ階層に必要です。
5. 「Commit changes」で保存します。
6. リポジトリの「Settings」→「Pages」で、
   Source：「Deploy from a branch」 / Branch：「main」 / Folder：「/(root)」
   を選び、「Save」します。
7. Pages欄の「Visit site」か、下記の形式のURLからアクセスします。
   https://<GitHubユーザー名>.github.io/gyomu-kenkyushitsu/
   （リポジトリ名を変えた場合はURLも変わります）
8. iPhoneのSafariで上記URLを開きます。
9. 共有（またはページメニュー→共有）→「ホーム画面に追加」を選び、
   「Webアプリとして開く」をオンにして「追加」します。
10. ホーム画面の「業務研究室」を起動し、
    設定→「オフライン利用」の準備完了を確認します。
11. 一度機内モード等で通信を切って、アプリの再起動を試します。

■ 更新方法
GitHubリポジトリの「Add file」→「Upload files」で、
同じファイル名の更新版を上書きコミットします。GitHub PagesのURLは変えないでください。
公開後、ネット接続中にアプリの「設定」→「新しい版を確認」。
更新が見つかったら「更新を適用して再起動」を押します。
データ保護のため、アプリ更新前には必ず暗号化バックアップを取ってください。

■ データ保存について（重要）
・業務記録、TODO、通勤記録等は端末内のIndexedDBに保存されます。
・IndexedDBが使えない場合に限りlocalStorage、両方不可の場合は一時メモリになります。
・GitHub PagesにはアプリのHTML/JS/CSS/アイコンのみを配置します。
・「暗号化バックアップの書き出し」は設定画面から行います。
・GitHub Pagesのリポジトリおよび公開ページは原則公開されます。
  顧客情報、会社の個人情報、秘密情報、バックアップファイルをリポジトリに入れないでください。
・会社が個人端末への業務情報保存や公開サービス利用を禁止している場合は記録しないでください。
・Safariの記録とホーム画面に追加したアプリの記録は、自動同期されません。
  ネット上の公開URLを変えると、既存のローカル記録を自動で読み込めない場合があります。
・アプリ内の通常保存領域は暗号化されていません。端末ロックや暗号化バックアップを利用してください。
・iOSは状況によりWebアプリの保存データやキャッシュを消去することがあります。
  大切なデータは暗号化バックアップを定期的に作成してください。
・「オフライン」はアプリ本体のキャッシュを意味します。新しいバージョンの取得や
  GitHubからの初回ダウンロードには通信が必要です。
・AI用プロンプトの生成はローカルで行いますが、外部AIに貼り付けると入力情報が送信されます。

■ PCでローカルテストする方法
このフォルダをターミナルで開き、Pythonがあれば次を実行:
    python -m http.server 8000
ブラウザから http://localhost:8000/ を開きます。
file:// 形式でHTMLを直接開いた場合、Service Workerは動作しません。
（localhost/HTTPSが必要です）

■ アプリの主要ファイル
index.html           アプリの入口
app.js               業務記録・TODO・通勤記録など
styles.css           クラシックなビジネス手帳の見た目
manifest.webmanifest ホーム画面アプリの設定
sw.js                オフラインのための静的ファイル保存
icon*.png, .svg      アプリアイコン
apple-touch-icon.png iPhoneホーム画面用のアイコン
.nojekyll            GitHub Pagesでの静的配信補助

【プライバシー】外部API、解析サービス、広告スクリプトは実装していません。
ただし公開ホスティングを使うと、サイト閲覧時のアクセス元情報はホスティング提供者等に
記録される可能性があります。通信不要な「完全なローカル専用」の配信とは異なります。
